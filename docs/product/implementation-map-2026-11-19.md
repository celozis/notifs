# Перенос согласованного дизайна в WPF

Поведение Q1–Q46 утверждено. Дополненные экраны прототипа ожидают визуальной оценки; тела GitHub-тикетов обновляются после неё. Этот файл задаёт распределение работы, а правила функций остаются в [спецификации](design-spec-2026-11-18.md), оформление — в [Master](../../design-system/notifs/MASTER.md).

## Перед началом тикета

1. Прочитать AGENTS.md, продуктовую спецификацию, Master и README эталона; открыть автономный notifs-reference.html.
2. Найти относящиеся к тикету экраны/состояния в reference/screens и его критерии ниже.
3. Реализовать доменную часть и WPF-представление; образец JavaScript остаётся демонстрацией, не архитектурой приложения.
4. Проверить поведение примерами спецификации и сравнить WPF с соответствующим снимком при одинаковом логическом размере/DPI. Завершение требует и поведения, и совпадения оформления.

Отдельная новая работа: **«Занятия задачами: начало, пауза, продолжение, отмена и вопрос по активному времени»**. Создать самостоятельный тикет после визуальной оценки. Его зависимости — локальные задачи/оценка (#2/#3) и доставка (#4); потребители — календарь (#8) и восстановление (#9). Он покрывает все правила раздела «Занятия и активное время» и проверочные примеры; отдельного отчётного трекера времени нет.

## Условия завершения передачи другим чатам

- Новые экраны получили визуальную оценку, результат записан рядом с эталоном.
- Master/tokens, спецификация и GitHub описывают одинаковые текущие правила; старые противоречащие пункты заменены или помечены историческими.
- Исходники, автономный просмотр, снимки и проверочные сценарии доступны в одной опубликованной ветке/коммите.
- Каждый тикет имеет ссылку на свои экраны и конкретные проверки; работа с занятиями имеет явного владельца в плане.
- Пользователь получает точку продолжения для нового чата. Наличие HTML-образца само по себе не означает готовность WPF-функции.
