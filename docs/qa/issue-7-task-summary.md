# #7 — периодическая сводка задач

20 ноября 2026. Исходная точка `29c4636`, ветка `codex/graphite-task-workspace`.

## Реализованный путь

В настройках добавлена «Периодическая сводка»: включение, положительный целочисленный интервал в минутах, 1–10 задач, дата и местное время первой сводки. Исходно включена, 180 минут, 3 задачи; первое время при миграции назначается через три часа с точностью до минуты. Дальнейшие моменты считаются от сохранённого начала. Открытие окна, сохранение звука/лимита и перезапуск не запускают новый отсчёт.

SQLite v6 → v7 добавляет отдельную запись настроек и сохраняемый следующий момент. Явное сохранение обеих секций атомарно; ошибка поля или SQLite сохраняет ввод и прежние данные. Чужие секции настроек не перезаписываются. При текущем варианте приложения мониторные/фоновые настройки ещё относятся к #15/#9.

Планировщик использует все обычные незавершённые задачи, включая задачи с личным расписанием. Список и его фильтр не участвуют в отборе; порядок задаёт существующая исходная срочность. Личная отсрочка исключает задачу до её настенного срока и удаляет строку из видимой и ожидающей сводки. Вопрос занятия — независимый вид события; личная отсрочка его не снимает.

Карточка общего нативного стека показывает «NOTIFS · СВОДКА ЗАДАЧ», «Вернёмся к делам?», ранги, названия и возраст. Пустой результат не публикуется. Для длинного состава прокручивается содержание, а «Открыть задачи» закреплено под ним. Действие открывает страницу списка с прежним фильтром, без скрытого отбора только по составу сводки. Выполнение/удаление убирает только нужную строку, пустая карточка исчезает без нового звука.

Повторная обработка сохраняемого момента не создаёт дубль. При просрочке обработки в минуту или больше старый периодический момент потребляется без показа; следующий остаётся на исходной сетке. Это техническое окно своевременной доставки минутного расписания, а не восстановительная сводка. Одно сообщение о пропущенных актуальных событиях после сна/выхода реализуется отдельно в #20.

## Проверки

Границы согласованы пользователем: публичные команды TaskService с временной SQLite и управляемыми часами, общий NotificationDelivery и пользовательский путь через настоящий WPF-стенд. Красные прогоны предшествовали добавлению границ сводки/формы/hover и исправлению звука.

Прикладные сценарии проверяют пример практическая/домашка/курс с рангами, противоположными срочности; закреплённое начало; повторные poll; сохранение лимита без повтора; отсутствие личного расписания; завершение между моментами; личную отсрочку и повторное открытие базы; возвращение после срока; пустой состав; пропуски за неделю; возраст; выключение/включение; диапазоны; миграцию v6; ошибку записи курсора с последующим успешным повтором; гонку завершения/отсрочки с уже полученной пачкой.

Общая доставка проверяется на двух видах событий, ожидании при hover, немедленной обработке действий, удалении строк из ожидающего события и независимом вопросе занятия. Звук ограничивается при первом поступлении; выход из hover и перерисовка молчат.

WPF проверяет явное сохранение, фокус ошибочного поля, сохранение ввода и откат обеих секций при SQLite-trigger ошибке, ширины 1010/768/375/320 DIP, отсутствие горизонтального переполнения, доступность сохранения, настоящий foreground HWND и фокус печати при доставке, действие полного списка с прежним фильтром, пустой состав и выборку 10 из 200 задач с длинными названиями. Перезапуск сохраняет настройки и потреблённый момент без восстановления старой видимости.

Через Computer Use в отдельной `.scratch/issue-7-manual` базе проверены открытие настроек, видимый фокус Tab, выделение Ctrl+A, ввод `11` в лимит и отказ сохранения с сообщением и возвратом фокуса к полю. Тестовое окно закрыто; пользовательская база не использовалась.

## Границы

Сеансы занятий/настоящее «Ещё 30 минут» ещё реализуются в #16/#17: текущая сводка не читает и не использует состояния занятия, а независимость вида CheckIn проверена через общую доставку. Ручные сортировки #13 также не входят в этот тикет; выборка сводки всегда прямо использует исходную срочность Core.

Для сводки переиспользуется общий вывод на основной монитор и общая остановка автоматического показа при наведении. Полная стабилизация геометрии, выбора фокуса и актуализации всех источников остаётся в #14; выбор монитора/fullscreen — #15, трей — #9, системное восстановление — #20. Физическая смена DPI, экранный диктор, слышимость звука, дополнительный монитор и системный сон здесь не проверялись. Имитация 150%/200% проверяет раскладку содержимого и не заменяет физическую смену DPI.

## Воспроизведение

Сборка/полный набор: `.\build.ps1 -Test`. После сборки целевые проверки: `& .\.scratch\dotnet\dotnet.exe tests/Notifs.Scenarios/bin/Release/net10.0-windows/Notifs.Scenarios.dll --summary` или `--summary-ui`. Запуск приложения: `.\build.ps1 -Run`.

Ручной маршрут: создать несколько невыполненных задач → включить сводку, интервал 1 минута, лимит 2, первая дата сегодня/время следующей минуты → сохранить → дождаться карточки → выполнить одну из задач → проверить оставшуюся строку → «Открыть задачи» → перезапустить и проверить сохранённые настройки. Личную отсрочку проверять через карточку личного расписания.

Локальные журналы: `.artifacts/issue-7-build.log`, `issue-7-core.log`, `issue-7-ui.log`; красные прогоны — `issue-7-red.log`, `issue-7-ui-red.log`, `issue-7-hover-red.log`, `issue-7-hover-sound-red.log`.
