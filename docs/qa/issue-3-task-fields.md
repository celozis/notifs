# #3 — дедлайн, полная оценка и срочность

Проверка 20 ноября 2026, Windows x64, .NET SDK 10.0.404. Исходная точка: `c14c8a922aa5b43d0eff6c5f3922f4b8ed2382b0`, текущая ветка `codex/graphite-task-workspace`.

## Пользовательский сценарий

- В существующем редакторе: необязательные дата и отдельное время дедлайна; целые часы и минуты полной оценки; пять буквенных рангов с исходным B. Частичный/невалидный ввод сохраняется вместе с остальными полями, фокус возвращается к ошибочному полю. Очистка сохраняет отсутствие значения.
- Дата без времени хранится отдельно от точного времени. Её исключающая граница — начало следующего местного дня, а не 23:59:00. Расчёт использует `TimeProvider.LocalTimeZone`; создание/выполнение хранятся в UTC.
- В карточках видны ранг, срок/его отсутствие и полная оценка/её отсутствие. В подробностях дополнительно исходное создание, местный возраст, знаковый запас. Нулевой запас показан как «0 мин». Отрицательный запас до срока имеет отдельную подпись; просрочена только невыполненная задача с наступившим сроком.
- Прикладные `Create`, `Edit`, `List`, `ListAll`, `Timing`, `Order` доступны без WPF. Расчёты и сортировка используют заменяемое время. Полная оценка не расходуется со временем; расчётный календарный ориентир не становится дедлайном.
- Исходная срочность: просроченные по старейшему дедлайну; будущие по запасу, дедлайну и рангу; без срока по созданию и рангу. GUID служит последним устойчивым ключом. Выполненные ниже невыполненных, по недавнему завершению.
- Секундный таймер окна обновляет возраст/состояние/запас и порядок без чтения базы. Сохранение полей перечитывает SQLite. Выполненные/возвращённые карточки удерживают позицию до явного переключения фильтра или раздела.
- Транзакционная миграция v1 → v2 добавляет nullable-поля и B старым задачам, сохраняя ID, текст, создание и выполнение. Ошибка записи не сообщает успеха и сохраняет все поля формы.

## Проверки

Прикладная граница с настоящей временной SQLite и часами UTC+5: пустые поля/B, повторное открытие, очистка, недопустимые оценки/ранг, сохранение создания и оценки, последние секунды местного дня/следующая полночь, точный срок, положительный/нулевой/отрицательный запас, выполненная задача без просрочки. Проверены пример «практическая → домашка без оценки → курс», переход в просрочку, равенства по сроку/рангу/созданию и стабильность после перезапуска. Отдельная база v1 проверяет миграцию и дальнейшее сохранение новых полей.

Настоящие окна WPF: создание/изменение/очистка, 1 ч 30 мин → 90 мин, время без даты, невозможная дата, неверное время, нулевая/отрицательная/нечисловая оценка, сохранность ввода при ошибке SQLite, исходный B и все пять буквенных рангов. Проверены размер 26 DIP, точные пары заливки/текста, отсутствие декоративных остановок Tab, возврат фокуса после ошибки прикладной валидации, нулевой/отрицательный запас, старение, пересчёт порядка и удержание выполненной карточки. Новые поля проверены при ширинах 1010/768/375/320 DIP без горизонтального переполнения; ошибки привязок отсутствуют.

Настоящий ввод через Computer Use в отдельной `.scratch/manual-qa/issue-3`: Ctrl+N, ошибка времени без даты с сохранением текста, ввод даты, часов/минут, выбор A мышью, Ctrl+S и появление сохранённых значений в списке/подробностях. Пользовательская база не использовалась.

После исправлений ревью выполнен полный прогон существующих сценариев #2 и новых #3: **159 PASS, код выхода 0**. Release-сборка — **0 предупреждений, 0 ошибок**. Полный стенд также прошёл 200 задач, ошибки чтения/записи, выполнение/возврат, повторное открытие базы и увеличение содержимого 150%/200%.
