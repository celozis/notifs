# #2 — рабочее окно задач

## Реализовано в коде

- Графит/янтарь из MASTER/tokens, Segoe UI/Consolas, собственные геометрические векторные иконки 18 DIP.
- Постоянная левая навигация 178 DIP; ниже 550 — 58 DIP. Новая задача в навигации, настройки и локальное пространство внизу. Будущие разделы недоступны с поясняющими подсказками.
- Равные колонки с зазором 20, поля 25/30; ниже 850 — одна область с возвратом. Минимальная высота окна 420, создание/изменение в основной рабочей области.
- Локальные создание/изменение/выполнение/возврат. Схема SQLite v1 не меняется: сохранены прежние идентификаторы, создание и Markdown.
- Исходный фильтр «Все», счётчики, явное переключение фильтров и разделов пересчитывает состав/порядок. Выполнение и возврат удерживают строку/место даже после обычного обновления.
- Отдельное действие галочки, состояния всей карточки, зачёркивание и подпись выполнения; безопасный нативный Markdown без загрузки ресурсов.
- Валидация заголовка с сохранением текста, защита повторного сохранения, сообщение об успехе только после SQLite, повтор чтения, сохранение прежнего состояния при ошибке записи.
- Фокус формы, Enter/Space для подробностей, возврат к связанной карточке, доступные имена и подсказки иконок.

Поля дедлайна/оценки/ранга, занятия, постоянные черновики, удаление, расширенные фильтры, расписания, трей и автозапуск остаются за своими тикетами. Несохранённый ввод удерживается только в памяти текущего окна.

## Проверки и ограничения

Проверено 19 ноября 2026, Windows x64, .NET SDK 10.0.404 / runtime 10.0.15.

- Release-сборка решения: 0 ошибок, 0 предупреждений.
- Полный `Notifs.Scenarios`: все проверки прошли. Настоящая временная SQLite и управляемые часы; валидация, редактирование/повторное открытие, прежние ID/создание, исходный Markdown, выполнение/возврат/порядок, защита повторной отправки, ошибки чтения/записи и повтор.
- Настоящие WPF-окна: редактор внутри окна, клавиатурный фокус формы/возврата, точная клиентская ширина 1010/768/375/320 DIP, отсутствие горизонтальной прокрутки, длинные названия и Markdown, список из 200 задач с прокруткой до конца, целевые высоты кнопок. Ошибок XAML binding нет.
- Увеличение содержимого 150%/200% прошло как стресс компоновки. Это не физическая смена DPI мониторов.
- Отдельный ручной прогон инструментом computer-use на `.scratch/manual-qa`: создание мышью и Ctrl+N, ввод Markdown, сохранение Ctrl+S, выбор первой задачи нажатием на свободный фон карточки, выполнение второй через её галочку без смены выбора первой, удержание в «Не сделаны», история и возврат с сохранением строки.
- `git diff --check` и разбор XML XAML прошли.

Сборка и сценарии запускались напрямую через `.scratch/dotnet/dotnet.exe`, без изменения ExecutionPolicy. Первоначальная проблема отсутствующего SDK устранена после загрузки архива пользователем. В среде агента обычный сетевой restore зависал: зафиксированные пакеты скачаны с официального NuGet, затем `restore --locked-mode --source .scratch/nuget-feed -p:NuGetAudit=false` выполнен из локального источника. Отдельный онлайн-аудит уязвимостей NuGet не проводился; версии и content hash зафиксированы lock-файлами.

Для повторной проверки после восстановления зависимостей:

```powershell
& .\.scratch\dotnet\dotnet.exe build Notifs.slnx --configuration Release --no-restore
& .\.scratch\dotnet\dotnet.exe .\tests\Notifs.Scenarios\bin\Release\net10.0-windows\Notifs.Scenarios.dll
```

Непроверенные границы: физическое переключение между мониторами с разным DPI, экранный диктор, совместимость со всеми конфигурациями Windows. Фон/расписания/нативные уведомления не входят в #2. Ручной прогон мышью и клавиатурой выполнен на обычной ширине; узкие состояния и фокус проверены автоматизированным WPF-сценарием.
