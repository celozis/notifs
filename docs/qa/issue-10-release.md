Проверки: 20–21 ноября 2026, Windows x64, SDK 10.0.404, runtime 10.0.15. Исходная точка изменений: `fa2ee0093133924f4900c50b5c04df46f1c344b6`. Эталон: комплект `f0462998e790e7fd9b4efce4ed8e0a4722875b71`, [правила Q1–Q46](../product/design-spec-2026-11-18.md), [Master](../../design-system/notifs/MASTER.md), [инструкция сравнения](../../design-system/notifs/reference/README.md).

Полная нативная приёмка #10/#15/#20 остаётся незавершённой: второй монитор и игра недоступны; пользователь прямо разрешил зафиксировать непроверенные пункты. Отсутствие оборудования не считается успешной проверкой. Тикеты в GitHub этим отчётом не закрываются.

## Воспроизведение проверок

Из корня репозитория, в интерактивной Windows-сессии:

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Test
powershell.exe -NoProfile -ExecutionPolicy Bypass -File .\build.ps1 -Publish
& .\.scratch\dotnet\dotnet.exe tests/Notifs.Scenarios/bin/Release/net10.0-windows/Notifs.Scenarios.dll --portable .artifacts/Notifs-win-x64
```

Целевые флаги после сборки: `--sessions`, `--check-in`, `--range`, `--reminder-calendar`, `--monitors`, `--recovery`, `--features-ui`, `--release-ui`. Стенд использует временные SQLite-базы; обычная база пользователя не участвует. Запись автозапуска проверяется отдельным временным ключом реестра, а общие формы используют изолированный адаптер автозапуска.

Журналы текущего прогона находятся в игнорируемой `.artifacts`: `full-suite.log`, `features-ui-final.log`, `calendar-membership-red.log`, `portable-final.log`, `publish-final.log`. Снимки поставляются в Git ниже; журналы можно воспроизвести командами.

Итоговый полный прогон завершился с кодом 0: **671 PASS**, включая прикладные, SQLite, нативные WPF и фоновые процессные сценарии. Release-сборка: 0 предупреждений, 0 ошибок. Отдельный portable smoke завершился `PORTABLE PASS`: проверены SHA-256 файлов пакета, собственный runtime, обе папки и восстановление после сбоя. В старых UI-тестах непрерывного расписания большие скачки управляемых часов заменены последовательными минутными опросами: отсутствие опросов более минуты намеренно проверяется как неизвестный перерыв в RecoveryScenarios, а не как непрерывная работа.

Существенные регрессии проверены на согласованных границах TaskService + настоящая SQLite + управляемые часы, NotificationDelivery/маршрутизация, настоящие WPF-окна:

- 10 активных минут + час паузы + 5 активных дают 15; параллельные старты/продолжения сохраняют одно активное занятие.
- После «Ещё 30 минут», 10 минут работы и часа паузы остаётся 20 активных минут; та же оценка не перевзводит вопрос.
- Отмена сразу убирает задачу из «В процессе»; пауза убирает устаревшее календарное членство, основанное только на будущем вопросе.
- Продление вопроса в 23:40 до 00:10 добавляет задачу в уже непустой календарь следующего дня, сохраняя существующие экземпляры карточек и выбранную дату. Тест сначала воспроизвёл ошибку, затем прошёл после исправления.
- Двухнедельный пропуск даёт одно сообщение, не поток старых почасовых сигналов/сводок; долг сохраняет первую дату.
- Подавленное однократное событие переживает закрытие/повторное открытие базы и выдаётся ровно один раз; новый явный старт до первого опроса не ставится ошибочно на паузу.
- Выключенное повторяющееся правило сохраняет долг/историю, убирая активные будущие планы согласно #19. Старое противоположное ожидание в RecurringScenarios обновлено.

## Настоящие Windows-проверки и ограничения

Доступен один Generic PnP Monitor `\\.\DISPLAY1`, bounds 1920×1080, work area 1920×1032, 100% (96 DPI). Проверены настоящие HWND, foreground и Keyboard.FocusedElement: карточки размещаются в рабочей области без перехвата фокуса; обычное maximized окно не считается fullscreen, borderless foreground на весь основной экран считается, минимизированное окно не считается. Это не заменяет проверку конкретной игры или exclusive fullscreen.

Через Computer Use выполнено обратное протягивание в реальной месячной сетке от 15 к 6 ноября через строки: выбран непрерывный период 6–15 ноября, панель показала две соответствующие задачи. Затем Computer Use остановлен сигналом Escape; дальнейший ввод в окна прекращён. Проверка реального указателя над кнопкой стека не завершена. Искусственные Routed MouseEnter/Leave и доставка с recording output проверяют проводку/правила, но не заменяют физическое наведение.

| Не выполнено | Что необходимо для приёмки |
| --- | --- |
| Два физических монитора, отрицательные координаты, отключение/подключение выбранного экрана | Проверить оба маршрута, сохранение identity и отсутствие overlay на основном экране при недоступном дополнительном |
| Реальные 150%/200% и смешанные DPI, перенос между ними | Проверить геометрию, текст, поля и стек; программное увеличение содержимого старых сценариев это не доказывает |
| Игра, exclusive fullscreen, браузерный F11 | Проверить переходы fullscreen, foreground/печать и восстановление подавленных событий |
| Физический sleep/hibernate, lock/unlock и выход из Windows-сеанса | Проверить системные события, паузу после сна, продолжение при lock и сохранение карточек при сне |
| Реальный указатель над стеком при серии событий | Убедиться, что кнопка не сдвигается, явные действия работают, после ухода остаются два последних события |
| Полностью отключённая сеть и чистая машина без установленного SDK/runtime | Текущий portable smoke убирает пути SDK/runtime и задаёт недоступный proxy; это не отключение сетевого адаптера и не удаление SDK |
| Вход Windows с реальным пользовательским Run-ключом | В suite проверяются отдельный временный ключ и запуск `--background`, без выхода из пользовательского сеанса |
| Системный reduced-motion, screen reader, субъективная громкость | Отдельная пользовательская проверка; автоматические имена/фокус/нулевая длительность анимации не заменяют её |

## Поставка

Выходы `build.ps1 -Publish`: `.artifacts/Notifs-win-x64/Notifs.App.exe`, `.artifacts/Notifs-win-x64.zip`, `.artifacts/Notifs-win-x64.zip.sha256`. Внутри — runtime, SQLite, значок, звук, README и лицензии. Браузерный движок, прототипные JS/HTML и шрифты Windows не поставляются. `release-manifest.json` фиксирует коммит, признак незакоммиченных изменений, SDK/runtime и SHA-256 каждого файла.

ZIP имеет фиксированное время записей и устойчивый порядок. Две последовательные публикации одного состояния дали побайтово одинаковый ZIP (SHA-256 совпал). Проверка переносимости копирует пакет в две папки с кириллицей/пробелами, использует внешний изолированный профиль, убирает SDK из PATH/DOTNET_ROOT и проверяет реально загруженный `coreclr.dll` из папки пакета. После принудительного завершения собственного тестового процесса следующая папка восстанавливает задачи, сырой невалидный черновик, календарь, настройки раздела, слот удаления и занятие на последней сохранённой паузе.

Для обновления: «Выход» в трее, заменить папку программы, запустить новый EXE; данные находятся вне неё в `%LOCALAPPDATA%\Notifs`. После перемещения пересохранить автозапуск.
