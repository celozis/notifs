# #6 — подтверждаемые повторяющиеся дела

20 ноября 2026. Исходная точка `f33988e`, текущая ветка `codex/graphite-task-workspace`.

## Реализованный путь

Общая форма «Напоминания» поддерживает простой сигнал и дело с подтверждением. У дела есть фиксированное недельное/почасовое правило либо интервал после фактического выполнения в днях/часах, первое местное срабатывание и положительная частота повторных уведомлений. Поля меняются с режимом; невалидный ввод и ошибка записи сохраняют форму.

У расписания одно текущее дело со своим идентификатором и первоначальным сроком. Пропуски, выключение, отсрочка и изменение правила не заменяют эту дату. В списке показаны исходный срок, давность, включение, правило и последнее выполнение. Будущая дата не даёт досрочного «Готово».

«Готово» из окна или нативной карточки одной транзакцией снимает долг, сохраняет фактическое выполнение вместе с исходным сроком и назначает следующий цикл. Повтор старого действия не завершает другое дело и не создаёт вторую запись. Фиксированный график не сдвигается поздним выполнением; интервал отсчитывается от выполнения. Долг можно выполнить при выключенном расписании.

Повторы, обычная сохраняемая отсрочка и скрытие используют общую доставку. Скрытие не выполняет дело. Выключение прекращает доставку; включение сохраняет старый долг или создаёт одно дело с первой пропущенной датой. Смена на простой сигнал при долге требует отдельного подтверждения, Escape сохраняет введённую форму и прежние данные. История сохраняется при смене режима.

Подтверждение удаления предупреждает об исчезновении расписания, текущего дела и истории из календаря. Общий слот восстановления с задачами/сигналами возвращает эти данные после перезапуска, оставляя расписание выключенным. Старые видимые карточки не восстанавливаются. SQLite v5 → v6 сохраняет прежние записи; новые поля JSON имеют совместимые значения по умолчанию.

`TaskService.ListReminderCalendar(from, until)` использует полуоткрытый интервал моментов: исходная дата текущего дела, факты с исходным сроком и фактической датой, плановые будущие даты фиксированного правила и единственная известная дата интервала, включая выключенные расписания. У интервала с долгом следующая дата неизвестна. История доступна после смены на сигнал; визуальный календарь — #19.

## Прикладная проверка

Границы согласованы пользователем: публичные команды TaskService с временной SQLite и управляемыми часами, команды RemindersViewModel и действия уведомлений. Красные прогоны предшествовали реализации долга, выполнения, отсрочки, календарного интерфейса, давности и формы.

Проверены несколько пропущенных недель, первая дата, отсутствие дублей при повторном poll/выполнении, поздний фиксированный цикл, 14 дней и 2 часа после фактического выполнения, выключение с долгом/без долга, изменение правила, сохраняемая 30-минутная отсрочка, повторная доставка после скрытия, отказ/подтверждение снятия долга, общий слот удаления и перезапуск. Ошибка SQLite при выполнении откатывает изменение долга/истории/следующего цикла. Отдельная регрессия фиксирует переход с неизменённого фиксированного правила на сигнал: прошлый долг не проигрывается как сигнал. Миграционный пример содержит прежний JSON v5 без новых полей. Дополнительные регрессии проверяют изменение интервала после выполнения без возрождения первой выполненной даты и сохранение будущих календарных дат при выключении.

## Standards

Первое независимое ревью: два нарушения Master и одна эвристика. Отмена подтверждения возвращала фокус к полю режима вместо инициатора; исправлено сохранением исходного фокуса до блокировки формы, регрессионный тест сначала упал. ## Spec

Первое независимое ревью: два замечания. Изменение интервала после выполнения могло вернуть долг за старую первую дату; новая длительность теперь отсчитывается от последнего фактического выполнения, фиксированное новое правило также не возвращает потреблённые даты. Календарный API исключал известные будущие даты выключенных расписаний; теперь они доступны. Оба случая закреплены регрессиями. Границы календарного представления #19 и системного восстановления #20 сохранены.

Повторное независимое ревью: Standards — оба нарушения устранены, новых существенных замечаний нет; Spec — оба замечания устранены, открытых замечаний нет. Необязательное переименование Signal остаётся отложенной эвристикой. Итого открытых нарушений Standards: 0; открытых замечаний Spec: 0.
