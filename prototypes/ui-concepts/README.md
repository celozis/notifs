# Notifs — варианты дизайна

## Текущая версия после интервью

Поведение Q1–Q46 подтверждено 19 ноября 2026 года. Дополненный вид новых экранов ожидает визуальной оценки пользователя. Открыть `notifs-reference.html` напрямую либо запустить `python prototypes/ui-concepts/preview.py` и перейти по напечатанному адресу. По умолчанию Visualize и интернет больше не нужны.

Источники: исходный `notifs-workspace-prototype.html` плюс `workspace-additions.js`/`workspace-additions.css`; сборка — `build_reference.py`. Генерируемый `notifs-approved-workspace.html` показывается в чате, `notifs-reference.html` — автономный просмотр. Снимки и точные токены — в `design-system/notifs/`; актуальные правила — `docs/product/design-spec-2026-11-18.md`.

Данные демонстрационные. Черновики и настройки автономного прототипа хранятся только под ключом `notifs-approved-prototype-v1`, отдельно от WPF-базы. Кнопки под макетом управляют проверочными сценариями, а не входят в приложение. Настоящего фонового планировщика, трея и доставки на мониторы здесь нет.

Ниже сохранено историческое описание концептов и прототипа до grilling. Временные правила «несколько активных занятий» и «Ещё 15 минут» заменены согласованной сводкой. `--concepts` открывает старые варианты и требует локальный Visualize.

Новый объединённый прототип: `notifs-workspace-prototype.html`. Он использует графит/янтарь и компоновку синего варианта, цветные ранги, выбор по всей карточке, сохранение выполненной карточки, фильтры, «Сел делать»/«В процессе», месячный календарь с выделением периода и центральной панелью.

Идеи, временные решения и вопросы к будущему grilling: `docs/product/design-notes-2026-11-18.md`. Сначала пользователь оценивает новый прототип, затем уточняются правила. Основное WPF-приложение не меняется.

Временные концепты для выбора оформления и навигации. Основное WPF-приложение и пользовательская база ими не изменяются. Все действия происходят в памяти; обновление страницы сбрасывает изменения.

## Посмотреть

На этом компьютере с установленным Visualize:

```powershell
python prototypes/ui-concepts/preview.py
```

Откройте адрес, который напечатает команда. «Новая задача» слева открывает форму в той же рабочей области. Можно проверить Markdown-просмотр, валидацию, сохранение и переходы между разделами.

По умолчанию команда открывает новый объединённый прототип. Предыдущие четыре концепта открываются с аргументом `--concepts`; только у них есть переключатель вариантов снизу.

В новом календаре можно тянуть мышь через строки, выбрать даты полями либо использовать Shift+стрелки и Enter. Escape закрывает центральную панель. В разделе «В процессе» показано время начала; кнопка **под макетом приложения** позволяет дойти до вопроса после оценки без ожидания часов. Реальных системных уведомлений прототип не отправляет.

После уточнений добавлены «Сделать паузу», «Продолжить» и «Отменить». Пауза сохраняет остаток отсчёта и исключается из активного времени; отмена убирает только занятие. Кнопка «Промотать 15 минут» под макетом помогает проверить, что пауза не расходует остаток. Markdown-описание поддерживает оборачивание выделения звёздочкой (Shift+8), повторный ввод для жирного, Ctrl+B/Ctrl+I и кнопки форматирования.

Справа от действий выбранной задачи есть «Удалить»: подтверждение, отмена через «Оставить»/Escape и восстановление последней удалённой задачи. Удаление прекращает её занятие и напоминание; восстановленное занятие ставится на паузу.

Применены поиски UI/UX Pro Max `dragging movements --domain ux` (альтернатива перетягиванию), `keyboard focus modal --domain ux` (видимый и необрезанный фокус) и `keyboard focus navigation --stack wpf` (клавиатура). Поиск `modal focus trap --domain ux` не дал точного совпадения для удержания фокуса; для этого применён нативный HTML dialog как общее платформенное решение.

## Вопросы для выбора

- **Глубокий синий:** синий фон, светло-синие действия, постоянная панель подробностей.
- **Тёплый песок:** светло-коричневый фон и фиолетовый акцент, композиция ежедневника, раскрытие задачи прямо в списке.
- **Графит и янтарь:** тёмный графит, тёплые действия, крупная ближайшая задача и компактная очередь.
- **Слива и лаванда:** тёмная сливовая основа, лавандовые действия, выбор дня и недели над задачами.

Дедлайны, оценки, ранги, календарь, напоминания и настройки показывают предполагаемый интерфейс следующих тикетов, а не готовую реализацию этих возможностей.

## UI/UX Pro Max

Поиск `productivity desktop dark blue --design-system` снова предложил зелёную productivity-палитру и маркетинговую структуру; они не приняты для этого сравнения. Уточнение `navy blue --domain color` нашло **B2B Service: Professional navy + blue CTA**: применён принцип сочетания синего с синим, значения адаптированы под тёмную тему.

`brown warm --domain color`: **Diary & Journal App**, рекомендация **Warm journal brown + ink violet**. Это источник сочетания коричневого с фиолетовым; фон затемнён по запросу пользователя.

`dark mode --domain style`: **Dark Mode (OLED)**, источник рекомендаций по разделению тёмных поверхностей и светлым акцентам. `amber dark --domain color`: **Alarm & World Clock**, сочетание янтарного с тёмной основой. Графитовый вариант — авторская адаптация. Точная сливово-лавандовая палитра — авторская; отдельного подтверждённого совпадения в поиске нет.

`dark accessible pairs --domain ux` дал нерелевантные результаты; уточнение `color contrast --domain ux` вернуло **Color Contrast** (4,5:1 для обычного текста) и **Color Only** (текстовые отметки вместе с цветом). Контраст проверяется на собственных фактических парах цветов.

Существующий `design-system/notifs/MASTER.md` остаётся описанием первой реализации. После выбора концепта нужно обновить дизайн-систему и перенести согласованную структуру в WPF: постоянная левая навигация, создание и редактирование внутри основного окна, сохранение черновика при переходах.
