# Notifs

Персональные задачи для Windows: локальные задачи, Markdown, дедлайн, полная оценка, ранги, сохраняемые черновики, удаление с восстановлением личные напоминания и повторяющиеся простые сигналы с постоянными нативными карточками.

## Запуск

Нужны Windows x64 и .NET 10 SDK. Скрипт использует SDK из `.scratch/dotnet` либо установленный .NET 10. Из PowerShell в папке проекта:

```powershell
.\build.ps1 -Run
```

На новой машине команда ниже загружает официальный SDK 10.0.404 в папку проекта, восстанавливает зафиксированные зависимости NuGet, собирает и запускает приложение:

```powershell
.\build.ps1 -Bootstrap -Run
```

Если PowerShell сообщает, что выполнение сценариев отключено, запустите SDK напрямую из папки проекта:

```powershell
& .\.scratch\dotnet\dotnet.exe run --project .\src\Notifs.App --configuration Release
```

Эта команда собирает и запускает приложение без `build.ps1`.

Интернет нужен для первоначальной установки инструментов и зависимостей. Повседневная работа и просмотр Markdown выполняются локально. Для запуска уже собранного приложения через локальный SDK без восстановления зависимостей:

```powershell
& .\.scratch\dotnet\dotnet.exe .\src\Notifs.App\bin\Release\net10.0-windows\Notifs.App.dll
```

## Работа с задачами

- «Новая задача» слева или Ctrl+N открывает форму в том же окне. Ctrl+S сохраняет, Escape или «К задачам» возвращает список. Все поля сохраняются в независимых черновиках новой задачи и каждой изменяемой задачи, включая невалидный ввод и перезапуск. До «Сохранить задачу» списки и планировщик используют сохранённую версию. «Отбросить изменения» очищает только текущий черновик.
- В описании выделение + `*` добавляет обрамление, повторное нажатие добавляет ещё пару. Ctrl+B/Ctrl+I и кнопки переключают жирный/курсив; одно действие отменяется одним Ctrl+Z. Просмотр Markdown работает локально.
- «Удалить» в подробностях и редакторе открывает подтверждение внутри окна. «Восстановить удалённое» внизу возвращает последнее удаление с исходными данными, черновиком и личным расписанием. Слот единственный, переживает перезапуск и заменяется следующим удалением.
- Дедлайн необязателен: дата `ДД.ММ.ГГГГ` и отдельное время `ЧЧ:ММ`. Без времени действует весь выбранный местный день. Время без даты сообщает об ошибке. Очистка обоих полей снимает дедлайн.
- Полная оценка задаётся целыми часами и минутами (например, 1 час и 30 минут = 90 минут). Она должна быть положительной; оба пустых поля снимают оценку. Возраст задачи не уменьшает оценку. Ранг S/A/B/C/D выбирается цветной буквой, исходно B.
- Исходный порядок: просроченные по самому старому дедлайну, будущие по наименьшему запасу времени, без дедлайна по созданию. Запас = дедлайн − сейчас − полная оценка; отсутствие оценки означает ноль в формуле. Отрицательный запас до дедлайна отличается от просрочки. В подробностях видны создание, возраст, срок, оценка и запас; вычисления обновляются во время работы окна.
- «Все / Не сделаны / Сделаны» показывают счётчики, исходно выбраны все задачи. «Готово» и «В работу» сохраняют состояние, удерживая карточку на прежнем месте до явного переключения фильтра или раздела. «История» показывает те же выполненные задачи; возврат сохраняет ID и исходное создание.
- Ниже 850 DIP окно показывает список или подробности с возвратом к карточке. Ниже 550 DIP навигация остаётся слева в виде иконок с подсказками. Tab перемещает фокус, стрелки выбирают карточку, Enter/Space открывают подробности. Кнопка-галочка меняет состояние отдельно от выбора карточки.
- Markdown поддерживает заголовки, списки, жирный/курсив, блоки и строки кода, цитаты. Ссылки и изображения представлены текстом; удалённые ресурсы и HTML не выполняются и не загружаются.

Данные хранятся отдельно от приложения: `%LOCALAPPDATA%\Notifs\notifs.db` (SQLite). Для проверки с отдельной базой перед запуском задайте `$env:NOTIFS_DATA_DIR = 'полный путь к тестовой папке'`. Для возврата к обычным данным выполните `Remove-Item Env:NOTIFS_DATA_DIR`.

В редакторе раскройте «Личные напоминания», включите расписание и задайте местные дату/время первого срабатывания. Необязательный положительный повтор задаётся в минутах. Сохраните задачу. Планировщик работает на любой странице, пока запущен процесс. Справа снизу основного монитора появляются до двух карточек без перехвата фокуса; они остаются до закрытия. «Готово» завершает задачу, «Отложить» сохраняет следующую попытку по настенным часам. Крестик и «Скрыть все» меняют только видимость. Прежний стек после перезапуска не возвращается.

В «Настройках» доступны короткий негромкий звук и общая обычная отсрочка (исходно 30 минут), применяемые кнопкой «Сохранить настройки».

Пункты «В процессе» и «Календарь» пока недоступны. Трей, автозапуск, выбор монитора/fullscreen, стабильность стека при наведении и объединение пропущенных событий относятся к следующим тикетам. Закрытие основного окна полностью завершает приложение и закрывает карточки.

## Простые сигналы

В разделе «Напоминания» нажмите «Новое напоминание». Задайте название, содержание, дату/местное время начала и повторение: выбранные дни недели с временем либо минуту каждого часа (0–59). Первое срабатывание ограничивает начало правила: например, начало в 12:30 и минута 25 дадут первый сигнал в 13:25. Сигналы не создают обычных задач, не требуют «Готово» и не используют интервал после выполнения.

«Сохранить напоминание» (Ctrl+S) записывает правило; «К напоминаниям» или Escape отменяют изменения формы. Ошибка сохраняет ввод. «Выключить» сохраняет поля и убирает карточки; повторное включение ждёт следующего будущего момента без проигрывания старых сигналов. «Отложить» на карточке использует общую отсрочку из настроек по настенным часам. Закрытие и «Скрыть все» меняют только видимость.

Удаление требует подтверждения. Общий слот «Восстановить удалённое» хранит последнее удаление задачи либо сигнала и переживает перезапуск. Сигнал восстанавливается выключенным. Данные автоматически обновляются с SQLite v4 до v5 с сохранением задач, черновиков, личных расписаний и настроек.

## Проверка

```powershell
.\build.ps1 -Test
```

Стенд проверяет прикладной сценарий с настоящей временной SQLite-базой и управляемыми часами, затем открывает настоящие окна WPF и проходит создание, валидацию, редактирование, выполнение, историю, возврат и повторное открытие. Тестовые данные удаляются; пользовательская база не используется. Изображения интерфейса сохраняются в `.artifacts/ui-qa/`. Для визуальной части нужна интерактивная Windows-сессия.

Целевые сценарии #3 можно запускать отдельно после сборки: `& .\.scratch\dotnet\dotnet.exe tests/Notifs.Scenarios/bin/Release/net10.0-windows/Notifs.Scenarios.dll --fields` (поля/время/миграция) или `--fields-ui` (также формы WPF). Миграция SQLite v1 → v2 сохраняет старые задачи с пустыми сроком/оценкой и рангом B. Снимки, сравнение с эталоном и результаты — в [отчёте #3](docs/qa/issue-3-task-fields.md).

Целевые проверки текущего стенда: настоящее окно с редактором внутри, выполнение/возврат с удержанием карточки, повторное открытие SQLite, ошибки чтения/записи, ширины рабочей области 1010/768/375/320 DIP, длинный текст и увеличение содержимого 150%/200%. Увеличение содержимого не заменяет реальную смену DPI монитора.

**Статус реализации #2:** Release-сборка прошла без предупреждений и ошибок; полный сценарный стенд прошёл, включая 200 задач, реальные WPF-окна и временную SQLite. Проверены обычная ширина, 768/375/320 DIP, длинные названия/описания и увеличение содержимого 150%/200%. Отдельно пройдены настоящими мышью/клавиатурой создание, Ctrl+N/Ctrl+S, выбор фоном карточки, независимая галочка, выполнение и возврат из истории. Снимки реализации и границы проверки — в [отчёте #2](docs/qa/issue-2-workspace.md). Физическая смена DPI мониторов и экранный диктор остаются непроверенными.

## Устройство проекта

- `src/Notifs.Core`: прикладная граница задач, время и SQLite.
- `src/Notifs.App`: WPF, модели представления, нативный Markdown-просмотр без браузера.
- `tests/Notifs.Scenarios`: проверки прикладного поведения и реальных WPF-форм.
- `design-system/notifs/MASTER.md`: визуальные правила по UI/UX Pro Max; `tokens.json` и `Theme.xaml` содержат соответствующие семантические цвета и шрифты.

Основа: [WPF](https://learn.microsoft.com/en-us/dotnet/desktop/wpf/overview/), [Microsoft.Data.Sqlite](https://learn.microsoft.com/en-us/dotnet/standard/data/sqlite/) и [Markdig](https://github.com/xoofx/markdig). Требования: GitHub #1, #2 и `docs/product/interview-summary.md`.

Целевые проверки #11/#12: `& .\.scratch\dotnet\dotnet.exe tests/Notifs.Scenarios/bin/Release/net10.0-windows/Notifs.Scenarios.dll --drafts-ui`. Для #4 используйте `--notifications` (SQLite/управляемое время/общая доставка) либо `--notifications-ui` (также настройки, нативный стек и действия). Ручной изолированный стенд: `--manual-notifications` создаёт две тестовые задачи с первым событием через 40 секунд; `--typing-target` открывает отдельный процесс для проверки печати. Пользовательская база не используется. Результаты и границы проверки — в [отчёте #4](docs/qa/issue-4-personal-notifications.md).

Целевые проверки #5: `--signals` (расписания, SQLite, миграция и управляемые часы), `--signals-ui` (также форма, узкие размеры, ошибки записи, нативная доставка и восстановление после перезапуска). Перед запуском соберите решение. Результаты, снимки и границы проверки — в [отчёте #5](docs/qa/issue-5-simple-signals.md).
